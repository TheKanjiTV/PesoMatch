# PesoMatch pre-launch security audit

**Later local follow-up:** The user selected Laragon first. A dedicated password-protected CRUD-only MySQL account is now configured and its actual grants verified; data and APP_KEY were preserved. Local browser companion verification and updated test results are documented in [LOCAL-REFINEMENTS.md](LOCAL-REFINEMENTS.md). The original audit results below remain historical; public HTTPS/infrastructure controls still require the eventual deployment environment.

**Date:** 2026-10-13. **Decision: not approved for public production deployment.** Verified code-level fixes are listed below; TLS, production credentials, infrastructure encryption and operational controls remain open. This is a source/configuration review and local automated verification, not an independent penetration-test certificate or assurance that the system has no vulnerabilities.

## Scope and actual architecture

React 19 JSX, React Router 7 Data Mode, Vite 8, Tailwind, Lucide and deferred Three.js scenes; Laravel 12/PHP 8.4, Sanctum first-party session authentication, Eloquent and Laragon MySQL 8.4. The active router is `src/login.jsx`, using `src/platform/`; old feed/mock prototypes are not the active application. PWA and Android WebView companions use the same Laravel service. There is no Supabase/client database, external generative-AI API, payment processor, enabled marketing email or analytics SDK in the active graph. Résumé analysis uses a local text extractor and matching is an advisory content-based TF-IDF baseline.

The audit inspected active/public/legacy source, API and web routes, controllers, requests, models, migrations, private storage, session/CORS/proxy settings, environment exposure, reachable Git text history, npm/Composer manifests and lockfiles, browser behavior, assets and native source. No public deployment, Git rewrite, live key rotation, destructive database migration or production-data deletion was performed. The existing application encryption key and database credentials were preserved. Only the local PDF extractor setting was updated to the vetted replacement binary.

## Verification evidence

- `pnpm build`: passed on the final frontend source. The pre-existing deferred Three.js geometry chunk remains over 500 kB; it is not a security failure or an eagerly loaded Dashboard feature.
- `php artisan test --compact`: **62 passed, 589 assertions**, SQLite `:memory:` forced. Tests do not reset the MySQL account database.
- `node --test tests/account-client.test.mjs`: **3 passed**; request coalescing and account transition behavior retained.
- Current full browser run: **22 passed, 1 optional skipped, 23 tests total**, against the production preview. This includes the new privacy-readiness scenarios and existing role, workflow, profile, auth, animation and offline checks. Earlier fixture/encoding failures described during the initial audit were resolved; the current full run has no failing test.
- Automated Axe checks cover existing public/workspace scenarios and additional WCAG 2/2.1/2.2 A/AA tags on legal/privacy surfaces, both HC1/HC2 and 390 px mobile layouts. No violations in passing checks; no JavaScript exceptions or CSP violations in instrumented scenarios. Deliberate authentication/validation errors are not mistaken for JavaScript exceptions.
- The separate Android companion-origin scenario was skipped because PESO_MOBILE_ORIGIN was not configured for this full run. An earlier attempt to start temporary mobile servers was rejected by automatic approval review (“blocked by policy,” without a more specific reason). Main mobile browser layouts were verified; physical Android/iPhone and release signing remain unverified.
- MySQL additive migration applied: nullable account notice fields, the `privacy_requests` table and nullable enrollment consent evidence added. Existing users have no fabricated acceptance. Read-only health after fixture cleanup: **134 users, 1 original résumé, 10 source jobs, 18 source courses, 11 migrations, 33 foreign keys, 0 orphan references**. No original private PDF was opened, rewritten or deleted by this audit.
- `security:check-production` deliberately exits **1** on current local configuration: non-production environment, HTTP origin, non-Secure local cookie, administrative DB user and empty DB password. It passes configured key/debug/session/SameSite/proxy and updated extractor checks. Do not relabel this gate as passing.
- Secret scan and dependency summaries are reproducible; five Laravel log files had no matches for the current nontrivial environment secret values; generated raw audit output is ignored under `.local/` and contains no printed credential values. No Git history rewrite or key rotation was performed.
