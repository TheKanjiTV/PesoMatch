## Test and measurement evidence

Browser regression evidence:

- The full 28-scenario run completed with **26 passed, one skipped, one failed test assertion** in 12.3 minutes. The failure was the lazy-chunk fault-injection harness: the service worker handled the asset request, so page-level interception did not induce a failed module and the normal catalog rendered instead.
- Corrected that test to use a dedicated `serviceWorkers: "block"` browser context and assert that at least one chunk request was actually failed. This is test-only isolation; production PWA behavior is preserved and its separate tests passed.
- After the final header-dismiss/contact-encoding changes, rebuilt production and reran all five UI/mobile audit tests: **5 passed in 4.0 minutes**. This rechecks the complete 312-measurement matrix, drawer keyboard/WCAG 2.2 assertions, titles/links, 503 retry, 422 field focus/description, failed-module recovery and reserved-character email href. Therefore all **27 enabled browser scenarios have passing verification across the full and targeted runs**; this is not reported as a single clean 28-test full-suite run.

## External source verification

`node scripts/check-public-links.mjs` checks only the public source URLs in the two source catalog JSON files, official Help references and the privacy-rights reference. It sends no session cookie, account header or private payload. Its raw response summary is in ignored `.local/ui-public-links.json`.

- **12 REACHABLE**: ten PhilJobNet source listings, PhilJobNet contact and TESDA directory returned 200 without a login redirect. This checks reachability, not ongoing eligibility, vacancies or reuse permission.
- **18 AUTHENTICATION_REQUIRED**: TESDA course URLs returned 200 after redirecting to `https://e-tesda.gov.ph/login/index.php`. A visitor needs their own official TESDA account; no third-party credentials were entered.
- **4 INCONCLUSIVE**: BLE PESO directory, BLE bureau page, NPC contact and NPC data-subject-rights URLs returned 403 to the anonymous automated HTTP client. None returned 404/410. A separate web retrieval could read the [NPC rights page](https://privacy.gov.ph/data-subject-rights/) and [NPC contacts](https://privacy.gov.ph/contactus/); the two BLE URLs remained blocked to that tool too. Do not delete those authoritative links or falsely certify every external destination as working for every user.
